KaPul API

AI 模型聚合与分发网关 — 兼容 OpenAI / Claude / Gemini 协议，在统一控制台管理模型、分组、额度和 API Key。

OpenAI 兼容 多模型聚合 api.kapul.cn:66/v1

产品介绍

KaPul API 是一个 AI 模型聚合网关，把多个上游模型服务整理成统一 API。只需改 Base URL 和模型名，就能在任何兼容 OpenAI 的客户端中直接使用。

核心概念

  1. 控制台 — 注册、登录、充值、查看额度、创建 API Key。
  2. API 地址 — 客户端填写的 Base URL：https://api.kapul.cn:66/v1。
  3. 模型和分组 — 模型决定能力与基础消耗，分组决定线路、稳定性、适用客户端和倍率。

适用人群

  • 第一次用 API Key 接入 AI 工具的用户
  • 想把 KaPul API 配进 Cherry Studio、Claude Code、Codex CLI 或自写代码
  • 想搞懂模型倍率、分组倍率、固定消耗和额度消耗关系

阅读顺序

  1. 快速开始 — 5 分钟跑通第一次调用
  2. 创建 API Key — 学会分组和额度管理
  3. 计费与额度 — 理解消费逻辑
  4. 工具接入 — 按客户端配置

快速开始

5 分钟内完成注册、创建 Key 并发起第一次 API 请求。

1. 注册并登录

打开 KaPul API 控制台，按页面提示注册或登录。登录后确认账户余额或额度状态。

2. 配置 API 地址

大多数 OpenAI 兼容客户端把这个值称为 Base URL：

推荐地址：https://api.kapul.cn:66/v1

3. 创建 API Key

进入控制台令牌页面创建新 Key。名称写清用途，分组选 auto。详见 创建 API Key。

4. 选择模型

  • 日常 / 文本：gpt、claude、deepseek
  • 代码协作：codex、claude-sonnet
  • 图片生成：image（按次计费）

5. 第一次请求

curl https://api.kapul.cn:66/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-5.4-mini","messages":[{"role":"user","content":"Hello"}]}'
配置项填写值
API Key控制台创建的 Key
Base URLhttps://api.kapul.cn:66/v1
Model控制台支持的模型名

创建 API Key

API Key 是你调用 KaPul API 的凭证。任何拿到 Key 的人都能消耗你的额度，应像密码一样保管。

创建步骤

  1. 打开控制台令牌页面
  2. 创建令牌，填写用途名称（claude-code、cherry-studio 等）
  3. 分组选 auto
  4. 按需设置额度限制或过期时间
  5. 立即复制 Key 到密码管理器
⚠

安全警告 — 不要把 API Key 写进公开仓库、截图或聊天。提交前检查 .env 和终端历史。

分组说明

分组适用场景
auto推荐，失败时自动切换
Codex-Basic / Value / OfficialCodex 场景
CC-MAX / CC-KIROClaude Code / Anthropic
生图视频专用分组图像 / 视频任务

Key 管理建议

场景建议
日常客户端长期 Key + 额度上限
测试脚本低额度 Key，用完禁用
多个客户端每个客户端单独 Key
高风险实验独立 Key + 独立额度上限

在代码中使用

KAPUL_API_KEY=sk-your-key
KAPUL_BASE_URL=https://api.kapul.cn:66/v1
const res = await fetch(`${process.env.KAPUL_BASE_URL}/chat/completions`, {
  method:"POST",
  headers:{Authorization:`Bearer ${process.env.KAPUL_API_KEY}`,"Content-Type":"application/json"},
  body:JSON.stringify({model:"gpt-5.4-mini",messages:[{role:"user",content:"Hello"}]}),
});
console.log(await res.json());

何时重新生成

  • 怀疑 Key 泄露
  • Key 被写入公开仓库
  • 某客户端异常消耗额度
  • 迁移到新分组
  • 按用途拆分额度

计费与额度

费用包含三个维度：账户额度 → 模型消耗 → 分组影响。

额度说明

控制台用 quota 展示可用额度。调用模型消耗额度，充值或套餐增加额度。不同模型、分组、上下文长度均影响扣减速度。

消耗公式

最终消耗 ≈ token 数量 × 模型倍率 × 分组倍率 × 输出/缓存修正系数
  • 输入 token — 消息、提示词、上下文
  • 输出 token — 模型回复，通常更贵
  • 模型倍率 — 不同模型的基准消耗差异
  • 分组倍率 — 线路、渠道造成的差异
  • 缓存倍率 — Claude 等长上下文场景的额外规则

固定消耗模型

图片 / 视频 / 任务型模型按 次 / 秒数 / 任务 计费：0.06 / request

✓

建议 — 新手用 auto 分组。明确需要特定客户端时再绑定具体分组。

成本控制

  1. 低倍率模型先测试
  2. 测试 Key 设额度上限
  3. 批量任务先小样本
  4. 清理不必要上下文
  5. 图片 / 视频先确认固定消耗
  6. 多客户端分开 Key

异常排查

现象可能原因
消耗比预期高高倍率模型或分组
一次请求扣很多上下文太长
图片扣费明显按次 + 规格影响
未使用却有消耗后台重试 / 自动同步
失败也有记录网关重试，查看日志

异步生图任务

通过 API 提交图片生成任务，用任务 ID 查询进度并获取结果。所有请求需携带 Authorization: Bearer YOUR_API_KEY。

接口总览

接口用途
POST /images/tasks提交异步图片生成或编辑任务
GET /images/tasks/{task_id}查询任务状态与结果
GET /images/tasks/{task_id}/content/{index}获取受保护的图片正文

提交生成任务

curl -X POST "https://api.kapul.cn:66/v1/images/tasks" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-image-2-enterprise","prompt":"一只坐在月球上的橘猫","size":"1024x1024","n":1,"response_format":"b64_json"}'

返回 202 Accepted：{"task_id":"task_xxx","status":"queued"}

图片模型尺寸

模型默认支持
gpt-image-1-enterprise1024×10241024×1024 / 1536
gpt-image-2-enterprise1024×1024至 3840×2160（16 倍数，宽高比 1:3 ~ 3:1）
gpt-image-2-4K1024×1024合法 WIDTH×HEIGHT
grok-imagine-image1k / 1:1通过 extra_fields 表达尺寸

图片编辑

curl -X POST "https://api.kapul.cn:66/v1/images/tasks?action=edits" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -F "model=gpt-image-2-enterprise" -F "prompt=把背景换成夜晚东京" \
  -F "image=@input.png"

多图编辑：重复 -F "image=@..."。gpt-image-1 最多 4 张，1.5 / 2 最多 10 张。

任务状态与下载

状态含义
queued任务已接收
processing处理中
succeeded至少交付一张图片
failed任务执行失败
 
# 查询状态
curl "https://api.kapul.cn:66/v1/images/tasks/task_xxx" \
  -H "Authorization: Bearer YOUR_API_KEY"

# 下载图片
curl "https://api.kapul.cn:66/v1/images/tasks/task_xxx/content/0" \
  -H "Authorization: Bearer YOUR_API_KEY" -o result.png
⚠

浏览器 <img src> 不能附加 Authorization 头。前端请用 fetch 获取 Blob 后再用 Blob URL。

JavaScript 轮询

const BASE="https://api.kapul.cn:66/v1",KEY=process.env.KAPUL_API_KEY;
async function create(){return(await fetch(`${BASE}/images/tasks`,{method:"POST",headers:{Authorization:`Bearer ${KEY}`,"Content-Type":"application/json"},body:JSON.stringify({model:"gpt-image-2-enterprise",prompt:"未来城市",size:"1024x1024",n:1,response_format:"b64_json"})})).json()}
async function wait(id){while(1){const t=await(await fetch(`${BASE}/images/tasks/${encodeURIComponent(id)}`,{headers:{Authorization:`Bearer ${KEY}`}})).json();if(t.status==="succeeded")return t.result;if(t.status==="failed")throw Error(t.error);await new Promise(r=>setTimeout(r,2500))}}
const s=await create();console.log(await wait(s.task_id));

怎么选工具

你想做什么建议先看理由
日常聊天 / 翻译 / 总结Chatbox 或 Cherry Studio界面直观，适合首次配置
写代码 / 改项目Claude Code、Codex CLI、OpenCode适合项目目录
VS Code 里用 AICline无需切换编辑器
管理多个模型和 ProviderCherry Studio 或 LobeHub多 Provider 支持
验证 Key 是否可用OpenAI Compatible最通用
频繁断线需要排查常见问题排查先排网络和代理

新手推荐顺序

  1. 创建 API Key
  2. 理解 Base URL、API Key、Model 三个字段
  3. 聊天 → Chatbox 或 Cherry Studio
  4. 写代码 → Claude Code 或 Codex CLI
  5. 跑通后再配置第二个软件

三个最容易出错的地方

字段正确错误
API Key控制台创建的密钥多复制空格、填到模型名
Base URL软件要连接的地址有的要 /v1，有的不要
Model完整模型 ID简写或过期模型名

常见问题排查

快速检查清单

检查项正确状态
Base URL包含 /v1
API Key控制台创建的完整 Key
鉴权头Authorization: Bearer YOUR_KEY
模型名与控制台完整 ID 完全一致
分组当前 Key 的分组支持该模型

HTTP 状态码

状态码常见原因
400请求体格式错误
401Key 错误 / 过期 / 禁用
403分组、模型、代理或权限限制
404路径错误，常见漏了 /v1
429频率 / 并发过高
500上游异常或网关临时错误

最小定位方法

  1. 用 curl 测试同一个 Key 和模型
  2. curl 可用再检查客户端配置
  3. 换低倍率常用模型测试
  4. 换备用地址测试
  5. 到控制台日志看失败原因和实际扣费

常见错误码

错误原因解决
401Key 错误 / 禁用重新创建 Key
404模型名 / 分组核对控制台
429速率限制降频或升级套餐
额度不足余额耗尽充值或等重置
连接超时网络不通检查代理和网络
